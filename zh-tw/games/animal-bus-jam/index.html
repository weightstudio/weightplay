How to play

Only the first bus accepts passengers. A wrong color waits in the holding lane, in order. If that lane blocks before the active bus is filled, the terminal deadlocks.

  1. Check the active bus and its remaining seats.
  2. Dispatch only the front passenger of a queue.
  3. Use Undo before the holding lane becomes blocked.

世界與任務

三十座夜間轉運站都在滿載運作。只有當前公車能讓乘客上車，其他顏色都必須依照派出順序等待在候車通道。

所有決策都清楚可見：完整車隊、每條隊列、當前公車座位，以及每個已占用的候車位。失敗來自路線選擇，而不是隱藏車流或倒數計時。

遊戲系統

每條隊列只能移動最前方的乘客。顏色相符的乘客會立即登上當前公車。

顏色不符的乘客會進入候車通道；必須先清出最前方的乘客，後面的人才能上車。

當前公車坐滿後會發車，下一台公車成為當前目標；候車通道最前方顏色相符的乘客會自動上車。

候車通道已滿，且沒有露出的乘客能完成當前路線時，轉運站就會堵死。復原會回到精確的上一個狀態，重新開始會還原關卡。

玩法說明

  1. 選擇已解鎖的轉運站。
  2. 閱讀當前公車、剩餘座位，以及車隊中的下一台公車。
  3. 把未來顏色送進候車通道前，先比較每條隊列的最前方乘客。
  4. 在不堵死候車通道的前提下坐滿所有公車，解鎖下一個轉運站。

策略提示

  • 把每個候車位視為稀缺資源，而不是免費倉庫。
  • 送出未來顏色前，先確認它會不會成為最前方的阻塞點。
  • 候車通道接近滿載時，優先露出當前顏色。
  • 只要派出乘客改變了你規劃的候車順序，就立即使用復原。

關卡與難度成長

第 1 站教你熟悉流程；從第 2 站開始，錯誤路線可能造成真正的堵死。

後續章節加入第四條路線、更長的車隊、更多隊列與重複顏色，並以兩格候車通道取代固定的三車配置。

開發設計理念

四條路線同時使用顏色與字母代碼。固定車隊、先進先出候車通道、確定性的隊列與驗證過的解法，共同構成一個在手機與桌面上都清楚易讀的策略益智遊戲。完整介面使用置中的單一邏輯版面，最大寬度為 920 像素。手機、橫向與桌面畫面會一起縮放相同的控制項、點擊區、美術與遊戲座標，不會個別拉伸。因此觸控、滑鼠與鍵盤都操作同一套合法狀態。主畫面海報與開始遊戲動作獨立於關卡管理；關卡選擇、戰鬥、對話框與結果則各自保有界線清楚的內容與返回路徑。

常見問題

可以從隊列中間派出乘客嗎？
不行。每次只能移動露出的最前方乘客。
為什麼乘客進入候車通道？
只有當前公車能上客；其他路線都依派出順序等待。
為什麼轉運站堵死？
候車順序卡住了當前路線，而且沒有露出的乘客能解除阻塞。
所有轉運站都能解嗎？
可以。三十條記錄中的解法路徑都經過自動檢查。
支援哪些控制方式與螢幕尺寸？
遊戲規則支援觸控、滑鼠與鍵盤；介面會在指定手機、橫向與桌面視窗中以單一邏輯版面縮放。
進度會自動移到其他裝置嗎？
不會。目前只儲存在本機瀏覽器；其他瀏覽器設定檔或裝置會有獨立進度。
